What this stage solves, intuitively. The Jetson was last seen running JetPack 5.1.3, whose TensorRT 8.5 cannot run the networks the plan chose and for which the current ZED SDK is not built. This stage moves it to JetPack 6.2 (Ubuntu 22.04, Python 3.10, TensorRT 10), installs the camera kits, and measures what the GPU can actually do, because the whole perception design rests on that number.

B2.2 Check the board before touching it

  1. Try ssh jetson (or jetson-desktop.local). If it answers, record cat /etc/nv_tegra_release, df -h and sudo nvpmodel -q, and copy anything worth keeping in the home directory to the host. The plan notes the board was unreachable on 2026-10-21.
  2. Open the case (screws on the underside), check the module is seated, the fan's connector is on its header, and note the NVMe drive's size. Fit the new drive if needed: M.2 key M, one screw.

B2.3 Flash JetPack 6.2

  1. This unit is the J4012 Classic ("Super Mode NOT Supported" on Seeed's product page). Instructions for the "reComputer Super J4012" (a reset switch, mfi_recomputer-super-… images) do not apply.
  2. On the host: sudo apt install qemu-user-static sshpass abootimg nfs-kernel-server libxml2-utils binutils -y.
  3. Download Seeed's JetPack 6.2 (L4T 36.4.3) image for the Orin NX 16 GB from the Seeed wiki page "reComputer J4012 Flash JetPack" and check it with sha256sum against the wiki's value. Extract it with sudo tar xpf mfi_….tar.gz where there are 50 GB free.
  4. Force recovery. With the power off, fit a jumper between FC REC (pin 3) and GND (pin 2) on the J401's 12-pin button header (pins: 1 PWR BTN, 2 GND, 3 FC REC, 4 GND, 5 SYS RET, 6 GND, 7 AUTO ON, 8 DIS, 9 UART TXD, 10 UART RXD, 11 LED+, 12 LED−). Connect the USB-C port to the host with a data cable, then apply DC power.
  5. On the host, lsusb must show 0955:7323 NVidia Corp (the Orin NX 16 GB in recovery). If it does not, the board is not in recovery or the cable is charge-only.
  6. Flash from inside the extracted folder: sudo ./tools/kernel_flash/l4t_initrd_flash.sh --flash-only --massflash 1 --network usb0 --showlogs. It writes the NVMe drive in 2–10 minutes; do not interrupt it.
  7. Power off, remove the recovery jumper, power on, and complete the first-boot set-up on the monitor: user name, host name (for example hud-jetson), time zone, network.

B2.4 Configure

cat /etc/nv_tegra_release # record the L4T release; the ZED SDK installer must match it sudo apt update && sudo apt full-upgrade sudo apt install nvidia-jetpack # CUDA, cuDNN, TensorRT, if the image does not already have them sudo nvpmodel -q --verbose # list the modes; on the standard configuration 0 = MAXN, 1 = 10 W, 2 = 15 W, 3 = 25 W sudo nvpmodel -m 0 # MAXN (confirm the id from the list first) sudo pip3 install -U jetson-stats # jtop; reboot afterwards sudo apt install python3-venv git build-essential cmake

Run at MAXN, never MAXN SUPER: Seeed warns that the J401 carrier's cooling is insufficient for it and that enabling it may permanently damage the unit. MAXN SUPER only exists in NVIDIA's "super" flash configurations, so if nvpmodel -q --verbose lists it, the wrong image was flashed. Use jetson_clocks only for benchmarks.

  1. Remote access. Install an SSH key; install Tailscale if the course has internet; give the Ethernet port a static address for the audience link (for example 192.168.50.2/24; mini PC 2 will be .3).
  2. Python. Create one virtual environment with access to the system's TensorRT bindings: python3 -m venv --system-site-packages ~/hud-venv. Install pyzmq msgpack numpy pyubx2 pvlib pyyaml. Install PyTorch only from NVIDIA's wheels for JetPack 6 if a tool needs it (Ultralytics' export does).
  3. ZED SDK. Download the installer whose L4T release matches /etc/nv_tegra_release exactly: for Seeed's L4T 36.4.3 image, ZED_SDK_Tegra_L4T36.4_v5.5.1.zstd.run (the installer aborts on any mismatch). chmod +x it and run it; accept the Python API installation into the venv. Check the camera later with ZED_Explorer.
  4. DepthAI. pip install depthai in the venv (version 3.x on 2026-10-25, with aarch64 wheels for Python 3.9 and later), and add the udev rule Luxonis documents so the OAK-D enumerates without root.
  5. Renderer. Install raylib's Python bindings (pip install raylib); if no aarch64 wheel is available, build raylib from source for the desktop GL platform and use the bindings' source build verify.
  6. Repository. Clone the project; create the hud/ package skeleton (B4.1).

B2.5 Build the engines and measure

yolo export model=yolo11s.pt format=engine half=True imgsz=640 # on the Jetson: engines are device-specific trtexec --onnx=ufldv2.onnx --fp16 --saveEngine=ufldv2.engine # lane network, from the repo's ONNX export trtexec --loadEngine=ufldv2.engine --iterations=500 # per-inference time tegrastats --interval 1000 --logfile b2_baseline.log # idle baseline

Record each engine's per-inference time. The full GPU budget with depth running is measured in B4.8 once the camera is connected.

B2.6 If it goes wrong

SymptomResponse
Host does not see the boardNot in recovery mode, charge-only cable, or a USB hub in between; connect directly to the host.
Flash fails part wayRun it again from recovery mode; check free space on the host; use the exact image for the 16 GB module.
ZED installer refusesIts L4T version does not match /etc/nv_tegra_release; download the matching one.
Thermal throttling in jtopCheck the fan runs; you may be in a super mode; give the unit air in the car (B7).
