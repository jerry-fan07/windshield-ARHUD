10Software layout

The plan calls for a standalone hud/ package in the repository with no openpilot build dependency. The bench is where it is started. Everything below is the car's layout; the bench-only parts are marked.

10.3 Running it

python -m hud.tools.testcard --monitor pgu # T-A: set the flip python -m hud.roadsrc --source comma2k19:/data/c2k19/Chunk_1/.../3 --monitor road python -m hud.laned & python -m hud.detectd & python -m hud.planed & python -m hud.egod & python -m hud.hudd --monitor pgu --mode live --gain 0.45 python -m hud.tools.latency --port /dev/tty.usbmodem* # 200 samples, prints median / p95 python -m hud.scored --log runs/2026-10-xx.log --truth # the tables of chapter 11

A supervisor script starts the set, restarts a crashed process after 1 s and marks its topics stale, as the plan requires. On macOS each full-screen window is created on its own display by name, at physical resolution; the two monitors are identified in bench.yaml by their EDID names, since macOS may renumber them.

10.4 Environments

A new venv, ~/.venvs/arhud-hud (Python 3.12), separate from the CAD and MetaDrive venvs: the MetaDrive one is pinned to 3.11 and a GitHub commit for the simulator and must not be disturbed; the export tool runs there and writes files the bench venv reads. On the Jetson, after the reflash to JetPack 6.2 (build guide B2), the same package with TensorRT and the ZED SDK; the Mac's Core ML path is not installed there. Model exports (ONNX, Core ML) are produced by a script and not committed.
